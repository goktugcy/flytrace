# 03 — UX

## 3.1 Design principles

1. **Signal first.** The primary answer (where is my flight, did it take off) is above the
   fold, always. Maps and 3D are supportive, never blocking.
2. **Progressive disclosure.** Glance → scan → drill. Cards summarize; detail expands.
3. **Realtime without jank.** Live values animate smoothly (interpolated), never flicker.
4. **Mobile-first, thumb-friendly.** Primary actions in reach; sheets over modals on mobile.
5. **Dark-mode-first.** Designed dark, adapted light. Map, charts, and 3D tuned for dark.
6. **Accessible by default.** WCAG 2.2 AA: focus rings, semantic landmarks, reduced-motion,
   color-independent status, screen-reader labels on every live region.
7. **Fast perceived load.** Skeletons, optimistic UI, streamed content; never a blank spinner-only screen.

## 3.3 Key user flows

### Flow: Guest tracks a flight and converts
```
Landing → click "Track a flight" → Search "TK1980"
      → Flight page (live) → "Notify me on landing" CTA
      → Sign-up sheet (email or OAuth) → choose channel (Telegram/Push)
      → Watch created → confirmation toast → back to flight page (now shows "Watching")
```
Friction budget: ≤ 3 taps from CTA to a created watch (for push, since it needs no external link).

### Flow: Connect Telegram
```
Settings → Channels → "Connect Telegram"
      → app generates one-time link token → deep link t.me/FlyTraceBot?start=<token>
      → user taps → Telegram opens → /start <token> → notifier verifies token
      → account linked → settings shows "Connected as @user" + test-message button
```

### Flow: Delay/gate alert (system-initiated)
```
provider poll → ProviderUpdated (gate A12 → B7) → notifier matches watch rules
      → renders template per channel → sends → NotificationSent
      → dashboard "Recent notifications" updates over WS → push arrives on device
```

### Flow: Reconnect on flaky network (see 12-websocket)
```
WS drops → UI shows subtle "reconnecting" chip (not a blocking modal)
      → exponential backoff reconnect → on resume, client sends last-seen cursor
      → server replays missed deltas from Redis stream → UI reconciles silently
```

## 3.4 Page specifications

### 3.4.1 Landing page (marketing)
Sections, in order (full visual spec in [04](./04-design-system.md) and [13](./13-frontend.md)):
1. **Hero** — headline, subhead, primary CTA ("Track a flight"), secondary ("Explore map").
   Background: **React Three Fiber 3D Earth** with animated great-circle arcs + moving aircraft.
   Must lazy-init, respect `prefers-reduced-motion` (static globe fallback), and never block LCP.
2. **Realtime counters** — flights tracked now, events today, notifications sent (live via WS
   or polled; animated count-up; announced politely to SR only on settle).
3. **Feature cards** — realtime tracking, smart notifications, provider status, beautiful map.
4. **Live flight map teaser** — embedded MapLibre snippet with a curated region.
5. **How it works** — 3-step (search → watch → get notified).
6. **CTA section** — sign-up.
7. **FAQ** — accordion (data sources, accuracy, privacy, cost).
8. **Footer** — links, attribution (OpenSky), legal, status page.

Performance rules: 3D and map are code-split and below-the-fold-hydrated; hero text/CTA are
server-rendered and interactive immediately.

### 3.4.2 Global map (`/map`)
- Full-bleed MapLibre GL map, dark style.
- **Left/floating filter panel:** airline, altitude band, aircraft category, on-ground toggle,
  "only my watchlist".
- **Aircraft markers:** rotated to heading, colored by altitude band; hover → tooltip
  (callsign, alt, speed); click → side panel with mini flight summary + "open flight page".
- **Clustering** above density threshold; bbox-driven fetch on `moveend` (debounced).
- **Realtime:** subscribe to `viewport` channel; positions interpolated between updates.
- Empty/sparse viewport → gentle hint to zoom out.

### 3.4.3 Flight page (`/flights/:callsign/:date`) — the centerpiece
Layout (desktop: 2-column; mobile: stacked):
- **Header:** callsign, airline logo, route `IST → LHR`, status pill (Scheduled/EnRoute/
  Landed/Delayed/Cancelled), share button.
- **Live map (primary):** track polyline (flown = solid, projected = dashed great-circle),
  aircraft marker, origin/destination pins, follow toggle.
- **Live telemetry strip:** Altitude, Heading, Ground speed, Vertical speed, Distance flown /
  remaining, ETA. Each animates; each is an ARIA live region (polite).
- **Timeline:** vertical event timeline — scheduled/actual off-block, takeoff, top-of-climb,
  cruise, descent, landing, on-block — each with time + confidence + source badge.
- **Aircraft card:** type, registration, age, operator, seat map placeholder → links to
  aircraft page.
- **Airports card:** origin & destination — terminal, gate, weather **placeholder**, local time.
- **Weather placeholder:** clearly labeled "coming soon"; reserved layout to avoid CLS.
- **Flight history:** past legs of this callsign (mini list) → each links to its flight page.
- **Notifications panel:** if logged in → toggle per-event; if guest → sign-up CTA.

### 3.4.4 Airport page (`/airports/:iata`)
- Header: airport name, IATA/ICAO, city, local time, current conditions **placeholder**.
- Tabs: **Departures** / **Arrivals** (virtualized tables: time, flight, dest/origin, status,
  gate) with live status updates.
- **Map** centered on airport with runways overlay and live aircraft in the vicinity.
- **Runways** list (designator, length, surface).
- **Statistics:** on-time %, busiest routes, movements/hour sparkline.

### 3.4.5 Aircraft page (`/aircraft/:reg`)
- Header: registration, type, airline, hex (icao24), age, photo **placeholder**.
- Current/last flight (live if airborne).
- Recent flights list; utilization sparkline; map of last track.

### 3.4.6 Dashboard (`/app/dashboard`)
- **Tracked flights** grid: live cards (mini map, status, ETA, next expected event).
- **Recent notifications** feed (live).
- **Saved aircraft** and **saved airports** rows.
- **Quick settings**: channel status chips (Telegram connected? push enabled?).
- Empty states with clear CTAs (see §3.6).

### 3.4.7 Admin (`/admin/*`)
- **Providers:** table + cards — status (up/degraded/down), p50/p95 latency, error rate,
  last success, circuit state; manual "re-check" and "disable" toggles.
- **Queues:** per-queue depth, active/completed/failed/delayed, throughput chart, DLQ browser
  with retry/discard.
- **Cache:** hit-rate, memory, evictions, top key patterns, TTL histogram.
- **Flights:** count live, by airline, map heatmap, ingestion lag.
- **Logs:** filter by level/module/correlationId; tail mode.
- **Stats:** users, watches, notifications sent, events derived — time-series.

## 3.5 Loading, error, and live states

- **Skeletons** for every data region (cards, tables, map chrome) — no layout shift on load.
- **Optimistic UI** for watch add/remove, favorite toggle; rollback + toast on failure.
- **Realtime chips:** connection status ("Live" ● / "Reconnecting…" ◐ / "Offline" ○).
- **Stale data badges:** if a value hasn't updated within its freshness budget, show a subtle
  "as of HH:MM" hint rather than pretending it's live.

## 3.7 Accessibility specification (WCAG 2.2 AA)

- **Color:** status never conveyed by color alone — always icon + label. Contrast ≥ 4.5:1
  (text), ≥ 3:1 (UI/graphics). Validated in [04](./04-design-system.md).
- **Keyboard:** full operability; visible focus ring (2px, offset); logical tab order; skip-to-content.
- **Motion:** honor `prefers-reduced-motion` — disable 3D auto-rotation, parallax, count-ups;
  keep essential feedback.
- **Live regions:** telemetry uses `aria-live="polite"`; connection changes announced once.
- **Maps:** provide a non-map fallback (data table of nearby/relevant flights); map controls
  keyboard-reachable; markers have accessible names.
- **Forms:** labels, `aria-describedby` for errors, inline validation announced.
- **Targets:** min 44×44px touch targets; adequate spacing.
- **Screen-reader routes:** each page sets a descriptive `<title>` and an `<h1>`; landmark
  regions (`header/nav/main/aside/footer`).

## 3.8 Responsive breakpoints (UX intent)

| Breakpoint | Layout intent |
|-----------|---------------|
| `< 640` (mobile) | Single column, bottom tab bar, sheets, map full-screen with FAB filters |
| `640–1024` (tablet) | Two-column where it helps; rail collapses to icons |
| `> 1024` (desktop) | Full multi-column, persistent rails, map + detail side by side |

## 3.9 Microcopy & tone

- Confident, concise, human. "Wheels up." over "Departure event detected."
- Time is always explicit and localized; show timezone for airport-local times.
- Uncertainty is honest: "Estimated", "as of", confidence badges on derived events.
- Errors are actionable: what happened + what to do next.
